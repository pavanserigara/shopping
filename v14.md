## Bug 1: Coupon system not working

Debug the coupon/discount code feature (from the "extra features" pass) end to end — don't just re-save the same code, actually trace the flow and find where it breaks.

- **Tenant dashboard**: confirm creating a coupon (code, discount type — flat or percentage, discount value, optional expiry date, active/inactive toggle) actually saves correctly to the database and shows up in the coupon list immediately after creating it.
- **Storefront checkout**: confirm entering a coupon code at checkout actually:
  - Looks up the code correctly scoped to that tenant (a coupon created by Shop A must never apply to Shop B's storefront — verify tenant_id scoping here specifically, since this is exactly the kind of bug that slips through in a multi-tenant system).
  - Validates it's active and not expired.
  - Applies the discount correctly to the cart total (flat amount subtracted, or percentage calculated correctly, including not letting the discount take the total below zero).
  - Shows a clear success message ("Coupon applied — ₹X off") or a clear error message ("Invalid or expired code") depending on the result.
  - Carries the applied discount through into the final order total sent via WhatsApp and saved in the `orders` record — the discount must be reflected in what the shop owner actually sees, not just in the on-screen cart.
- Add basic logging/error visibility around this feature so if it breaks again, it fails with a visible error instead of silently doing nothing (which is likely what's happening right now).
- Test the full loop yourself: create a coupon as a tenant, apply it as a customer, confirm the order record and WhatsApp message both show the discounted total correctly.

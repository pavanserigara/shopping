# Upgrade prompt (v4) — Local Shop OS: navigation, bug fix, and branding

Paste this into Antigravity as a follow-up brief, after v1, v2, and v3 are built. This pass fixes a navigation gap, a responsive header bug, a broken post-order redirect, and adds a proper logo. Keep the yellow/white theme from v3 — this pass builds on it, doesn't replace it.

---

## Fix 1: Add bottom navigation to the storefront (mobile)

The storefront is currently missing a bottom navigation bar on mobile — this is a standard, expected pattern on e-commerce sites (Amazon/Flipkart/Blinkit-style) and customers will look for it.

- Add a **fixed bottom navigation bar**, visible only on mobile widths, with 4 icons:
  - **Home** — back to the storefront's product grid
  - **Categories** — opens the category filter/tabs
  - **Cart** — opens the cart drawer, with the live item-count badge (reuse the badge logic from the header cart icon)
  - **Orders** — a simple "my orders" view for that customer on that shop (see Fix 3 below — this ties into where the customer lands after ordering)
- Each icon has a label underneath it (small text, e.g. 10–11px) and highlights (fill/color change) when that section is active.
- Must stay fixed to the bottom of the viewport, not scroll away with the page content — but must not overlap the "Order via WhatsApp" button or product content; add bottom padding to the page content so nothing is hidden behind the nav bar.
- On tablet/desktop, hide the bottom nav — those layouts already have the header and sidebar space for the same actions.

## Fix 2: Landing page header — responsiveness and button sizing

The landing page header currently breaks/looks wrong on smaller screens.

- At mobile width, the header should collapse to: logo on the left, a compact hamburger menu (or a single "Start free trial" button) on the right — do not try to fit a full nav menu plus a large CTA button side by side on a narrow screen, it will overflow.
- Fix CTA button sizing specifically: buttons must scale down sensibly on mobile (don't let button padding/font-size stay fixed at desktop size and overflow the screen width) but must stay large enough to comfortably tap (minimum ~44px touch height).
- Re-check the header at 375px, 768px, and 1280px+ and confirm no text wrapping mid-word, no button overlap, and no horizontal scroll caused by the header specifically.

## Fix 3: Post-order redirect bug

**Current broken behavior**: after a customer places an order, they get redirected to the platform landing page.
**Correct behavior**: after placing an order, the customer must land back on that same shop's storefront (`/shop/{subdomain}`), not the platform landing page.

- On successful order submission, redirect (or in-page transition) back to the shop's storefront, with a clear confirmation state shown — e.g. a success toast/banner ("Order placed! We've sent it to [shop name] on WhatsApp") and/or a brief order-confirmation view before returning to browsing.
- This confirmation should also feed the "Orders" tab from Fix 1 — after ordering, that customer can tap "Orders" (bottom nav) and see their just-placed order status for that shop (track by a simple local/session identifier tied to their contact number, no login required).
- Audit the checkout flow end to end to confirm no step in the WhatsApp handoff or order POST accidentally redirects to the root domain instead of staying scoped to `/shop/{subdomain}`.

## Fix 4: General UI improvement pass
- Continue refining spacing, shadows, and card polish across the storefront and landing page on top of the v3 yellow/white theme — this pass should look like an iteration/refinement, not a new redesign.
- Pay particular attention to consistency between the new bottom nav, the header, and the cart drawer so they clearly feel like one connected system, not three separately built pieces.

## Fix 5: Create a platform logo

Design a simple, clean logo for the platform, in the yellow/white theme.

- Icon-based mark (not just a text wordmark) — something like a shopping cart, a storefront/shop outline, or a shopping bag, simplified to a clean geometric icon that reads clearly at small sizes (favicon, header logo, app icon).
- Use the yellow/white palette from v3: e.g. a yellow-filled icon on a white or transparent background, or a white icon inside a yellow rounded-square badge (common app-icon style) — pick one direction and apply it consistently.
- Deliver it as an SVG (scalable, crisp at any size) plus exported PNG sizes for favicon/app-icon use (e.g. 512x512, 192x192, 32x32).
- Use this logo consistently in: the landing page header, the storefront header, the tenant dashboard header/sidebar, the super admin panel, and the browser favicon.
- Keep it simple enough to still look clean at 24x24px (favicon size) — avoid fine detail that disappears at small sizes.

## What NOT to change in this pass

- Keep the yellow/white theme and design tokens from v3 — this pass adds to it (bottom nav, logo), it does not introduce a new palette.

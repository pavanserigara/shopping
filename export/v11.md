# Upgrade prompt (v11) — Local Shop OS: shop QR codes + mobile-responsive admin panels

Paste this into Antigravity as a follow-up brief, after v1–v10 are built. This pass adds a QR code feature for shop owners and fixes both admin panels (tenant dashboard and super admin) to be properly mobile-responsive — right now they're desktop-only layouts that overload on small screens.

---

## Part A: Shop QR code generator (tenant dashboard)

Add a new feature in the tenant dashboard (Settings or a new "Share My Shop" section) that generates a QR code linking to the shop's own storefront URL (`mydomain.com/{subdomain}`, per the clean URL structure from v8).

- Generate the QR code server-side or client-side (either is fine — pick whichever is more reliable in this stack) encoding the shop's storefront URL.
- **Unique branded design, not a plain black-and-white QR code**: use the platform's yellow brand color for the QR code's foreground/accent (while keeping it scannable — don't sacrifice scannability for style, test that it actually scans correctly after styling), and include the shop's logo (from v5) in the center of the QR code if the shop has uploaded one, with a clean white background so contrast stays high.
- Add the shop name as a caption/label displayed above or below the QR code image (visible in the downloaded file, not just on-screen), so a printed QR code is self-explanatory.
- **Download button**: let the tenant download the QR code as a PNG (and SVG if feasible) file, sized appropriately for both screen sharing and printing (e.g. provide a decent resolution like 1000x1000px minimum for the PNG so it prints cleanly on a poster/counter sign).
- **Share button**: a simple share action (native share sheet on mobile via the Web Share API if available, otherwise a "copy link" fallback) so a tenant can quickly send their shop link to customers via WhatsApp or elsewhere.
- Test that the generated QR code actually scans correctly and opens the right storefront URL — verify this on a real phone camera/QR scanner, not just visually.

## Part B: Make the tenant (shop admin) dashboard mobile-responsive

The tenant dashboard currently overloads on mobile — fix this with a proper mobile navigation pattern instead of squeezing the full desktop layout onto a small screen.

- Replace the desktop sidebar navigation with a **collapsible mobile menu** on small screens: a hamburger icon in a compact top bar that opens a slide-in or full-screen menu listing all dashboard sections (Products, Orders, Ads, Sales Report, Settings, Share My Shop, etc.), closing after a selection is made.
- Every dashboard page/section (product list, product add/edit form, order inbox, sales report, ads management, settings) must be individually re-checked at mobile width — tables should scroll horizontally or restack as cards, forms should stack to single-column, buttons should be full-width or appropriately sized for touch (minimum ~44px tap height, consistent with earlier passes).
- Don't just shrink the desktop layout — redesign the information density for mobile specifically (e.g. an order card on mobile should show the essentials compactly, with a tap-to-expand for full detail, rather than cramming the full desktop table row into a narrow screen).
- Re-check the current-plan indicator (from v7), locked-feature UI (from v6), and toast/confirmation popups (from v7) all still work and display correctly at mobile width — these were built assuming a desktop layout and need to be re-verified here.

## Part C: Make the super admin panel mobile-responsive

Apply the same treatment to the super admin panel.

- Same collapsible mobile menu pattern as Part B, covering all super admin sections: Tenants, Plans, Global Ads, User Management, Team/Admins, Settings.
- Tenant list, plan builder (with its feature checkboxes from v6), and any other table-heavy views need mobile-specific layouts — checkboxes and data tables are especially prone to breaking on narrow screens, so pay particular attention to the plan builder's feature checklist and the tenant list table.
- Verify all the AJAX-driven live updates and confirmation toasts (from v7) still work correctly on mobile.

## What NOT to change in this pass
- Don't touch the storefront or landing page — those were addressed in earlier passes. This pass is QR generation plus the two admin panels' mobile responsiveness only.
- Don't change the underlying data model, plan/feature-gating logic, or WhatsApp ordering flow.

## Deliverable
A working, branded, downloadable and shareable shop QR code feature in the tenant dashboard, and both the tenant dashboard and super admin panel fully usable and properly laid out on mobile — verified at mobile (~375px), tablet (~768px), and desktop (~1280px+) — with a working collapsible navigation menu replacing the desktop sidebar on small screens in both panels.

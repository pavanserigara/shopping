## Step 1: Rebuild the database table cleanly
Drop and recreate the coupon-related table(s) with this exact structure (adjust only if a genuine conflict with existing schema requires it, and note why):

```sql
coupons
  id INT PRIMARY KEY AUTO_INCREMENT
  tenant_id INT NOT NULL
  code VARCHAR(50) NOT NULL
  discount_type ENUM('flat', 'percentage') NOT NULL
  discount_value DECIMAL(10,2) NOT NULL
  min_order_amount DECIMAL(10,2) DEFAULT 0
  is_active BOOLEAN DEFAULT TRUE
  expires_at DATE NULL
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  UNIQUE KEY unique_code_per_tenant (tenant_id, code)
```

- The `UNIQUE KEY (tenant_id, code)` is important — it allows the same code text (e.g. "WELCOME10") to exist independently for different shops, while preventing one shop from creating the same code twice.

## Step 2: Rebuild the backend endpoint(s) cleanly
- Build a single, clearly defined endpoint for creating a coupon (e.g. `POST /admin/coupons/create`) that:
  - Requires the tenant to be authenticated (reuses existing session/auth check pattern from other tenant dashboard endpoints).
  - Validates all required fields server-side (code not empty, discount_type is one of the two allowed values, discount_value is a positive number, and if percentage, not over 100).
  - Inserts via a PDO prepared statement, scoped to the logged-in tenant's `tenant_id`.
  - Returns a proper JSON response with a clear success flag and message, or a clear error flag and message — never a raw PHP error, a blank response, or an HTML error page (this is very likely the actual cause of "AJAX error" — the frontend is probably trying to parse a non-JSON error response).
- Build matching endpoints for list, edit, delete, and toggle-active, following the same pattern.
- Build a separate, clearly defined endpoint for **applying a coupon at checkout** (e.g. `POST /storefront/coupon/apply`) that:
  - Takes the shop's `subdomain`/`tenant_id` and the entered code.
  - Looks up the coupon scoped strictly to that tenant — confirm this with an actual test using two different shops and two different coupon codes, not just a code review.

  - Calculates the discount correctly (flat: subtract fixed amount, capped at not going below zero; percentage: calculate off the subtotal) and returns the discounted total.
  - Returns clear JSON for both valid and invalid codes — "Invalid or expired code" for a bad code, never a generic failure.

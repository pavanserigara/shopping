# Upgrade prompt (v5) — Local Shop OS: desktop nav, admin controls, ad analytics, cart UX

Paste this into Antigravity as a follow-up brief, after v1–v4 are built. This pass fixes a missing desktop menu, a broken shops directory, adds real platform controls for the super admin, shop branding for tenants, ad view analytics, and a cart UX improvement. Keep the yellow/white theme and logo from v3/v4 — refine, don't replace.

---

## Fix 1: Desktop storefront is missing a menu/nav

On desktop widths, the storefront currently has no proper navigation menu (this only exists via the mobile bottom nav from v4).

- Add a **desktop header nav bar**: shop logo/name on the left, category links or a categories dropdown in the center/left-of-center, search bar, and cart icon (with live badge) on the right — this is the desktop equivalent of the mobile bottom nav, not a duplicate of it.
- Sticky on scroll, consistent with the header behavior already built in earlier passes.
- Hide the mobile bottom nav at desktop widths (it should already be mobile-only from v4 — confirm this is still correct) and confirm the desktop header carries the same navigation actions (home/categories/cart) instead.

## Fix 2: "Explore shops" (shop directory) page is not working

The `/shops` public directory page from v2 is broken — fix it end to end.

- Confirm the route loads and correctly queries all tenants where `plan_status` is active (don't show suspended/trial-expired shops here, see Fix 3 for trial logic).
- Confirm each shop card links correctly to its own `/shop/{subdomain}` storefront.
- Confirm category filtering and search on this page actually filter the results (check the JS/AJAX wiring, not just the UI).
- Test this page at mobile and desktop widths — it should follow the same design system as the rest of the platform.

## Fix 3: Super admin — tenant feature controls (limits + trial management)

Add real platform controls to the super admin panel so the platform owner can manage what each tenant is allowed to do, not just view them.

- **Product limit per tenant**: super admin can set a maximum number of products a shop is allowed to list (e.g. a default limit like 30 products on trial/basic plan). Store this as a `product_limit` column on `tenants`. Enforce it when a tenant tries to add a new product — block the add and show a clear message ("You've reached your product limit — contact support to upgrade") once the limit is hit.
- **Trial duration control**: super admin can configure how many days a new signup's trial lasts (don't hardcode 15 days — make it an editable setting, e.g. a `trial_days` platform setting with a sensible default of 15).
- **Trial status visibility**: for each tenant, the super admin panel must clearly show whether that tenant is currently on trial, trial expired, or on a paid plan, plus the exact trial end date. Compute this from `created_at + trial_days` compared to today, or from an explicit `trial_ends_at` column set at signup.
- **Expired trial behavior**: when a tenant's trial expires and they haven't been marked as paid, their storefront should show a "temporarily unavailable" state (same pattern as a suspended tenant from v1) until the super admin marks them active/paid.
- Build a simple settings area in the super admin panel where these platform-wide defaults (default trial days, default product limit) can be edited without touching code.

## Fix 4: Shop admin — upload a shop logo

Add a shop logo upload to the tenant dashboard (Settings section).

- Tenant can upload a logo image (stored per-tenant, e.g. `/uploads/{tenant_id}/logo.*`), with a preview before saving.
- This logo replaces the generic shop-name text (or sits alongside it) in: the storefront header, the shop directory card (Fix 2), and anywhere else the shop is represented on the platform.
- If no logo is uploaded, fall back cleanly to a text-based placeholder (e.g. the shop's initial in a colored circle) rather than a broken image icon.

## Fix 5: Shop admin — ad management with view analytics

Extend the ad system from v2 so the tenant admin can see how their ads are performing, not just upload them.

- On every ad impression (banner or mid-page ad rendered on the storefront), log a lightweight view event: `ad_id, tenant_id, viewed_at`. Keep this simple — a count is enough, no need for user-level tracking.
- In the tenant dashboard's Ads section, show each ad with its view count (e.g. "1,204 views since [date]") next to the existing upload/schedule/activate controls from v2.
- If feasible in this pass, also show a simple trend (views today / this week) — not required if it adds too much complexity, total view count is the minimum bar.

## Fix 6: Icon and visual style — more yellow, Android/Material-style

- Increase the use of the brand yellow specifically in icons across the storefront and dashboard (nav icons, cart icon, category icons, status icons) — right now they read as too neutral/gray; icons should feel branded, not default.
- Adopt a consistent **Material Design-inspired icon style** (rounded, filled or outlined consistently — pick one style and use it everywhere, don't mix outlined and filled icons across the app) so the whole UI feels like a cohesive, modern Android-style app rather than a generic web template.
- Active/selected states (bottom nav item, category tab, cart badge) should use the brand yellow prominently so state changes are obvious at a glance.

## Fix 7: Add-to-cart confirmation popup

When a customer taps "Add to cart" on a product, show a brief confirmation popup/toast instead of silently updating the cart badge.

- Toast content: product name/thumbnail + "Added to cart" message, with two clear actions: **View Cart** and **Checkout** (or **Continue Shopping** to dismiss).
- Auto-dismiss after a few seconds if the customer doesn't interact, but tapping "View Cart" or "Checkout" should immediately open the cart drawer/checkout flow.
- Keep this lightweight (a toast/snackbar pattern, not a full-screen modal) so it doesn't interrupt browsing for customers who want to keep adding items.

## Fix 8: Product card UI improvement

Iterate further on the product card design from v1/v3 — this should look more premium.

- Add a subtle elevation/shadow and hover state (desktop) or press state (mobile) so cards feel tappable/interactive.
- Tighten the type hierarchy: product name should be clearly readable but not compete with the price; price should be the most visually prominent text on the card after the image.
- Make sure the "Add to cart" button on the card is a clear, thumb-friendly tap target on mobile and doesn't shift/reflow the card layout when stock status text changes length (e.g. "In stock" vs "Only 2 left").
- Ensure card sizing stays consistent across a full grid row even when product names vary in length (truncate long names with ellipsis rather than letting cards grow unevenly).

## What NOT to change in this pass
- Don't touch the WhatsApp ordering backend logic or the multi-tenancy/tenant_id scoping.
- Keep the yellow/white theme and logo from v3/v4 — this pass intensifies and refines it, it does not introduce a new palette.

Right now, updates in both the tenant dashboard and the super admin panel require a manual page refresh to see the result. Fix this everywhere.

- Every create/update/delete action (adding a product, updating an order status, saving ad settings, editing a plan, assigning a plan to a tenant, etc.) must be handled via AJAX and update the on-screen data immediately — no full page reload required to see the new state.
- Show a small confirmation popup/toast on every successful action (e.g. "Product added," "Order status updated," "Plan saved") — reuse the toast/snackbar pattern already built for the add-to-cart confirmation in v5, extend it to admin actions.
- On failure, show a clear error toast instead of a silent failure or a broken page.
- Apply this consistently across the tenant dashboard (products, orders, ads, settings) and the super admin panel (tenants, plans, global ads, settings) — audit every form/action in both panels, not just the newest ones.

## Fix 6: Rebuild the landing page as a real SaaS application landing page

The current landing page doesn't yet look like a proper SaaS product page (think Notion, Linear, or similar caliber — clean, modern, persuasive). Rebuild it with that bar in mind.

- Add scroll-triggered animations: sections should fade/slide in as the user scrolls down (subtle, not gimmicky — e.g. a gentle fade-up on each section as it enters the viewport).
- Add a sticky header that changes appearance slightly on scroll (e.g. adds a shadow/background once the user scrolls past the hero) so it feels alive, not static.
- Strengthen the hero section: a strong headline, a short supporting line, a primary CTA ("Start free trial") and a secondary CTA ("See how it works" — can scroll-link to the how-it-works section).
- How-it-works section: consider an animated or interactive 3-step visual rather than static icons, if feasible.
- Testimonials/social proof: once real shops exist, pull this from real data; until then keep it as clearly-marked placeholder content (don't fabricate fake reviews as if real).
- Add an FAQ section addressing likely shop-owner objections (e.g. "Do I need technical knowledge?", "What happens after my trial ends?", "Can I cancel anytime?").
- Footer: proper sitemap-style links, contact/WhatsApp support link, and basic legal placeholders (Terms, Privacy) even if just placeholder pages for now.
- Full responsiveness re-check after this rebuild — mobile, tablet, desktop, per the same bar as previous passes.

## Fix 7: New features to add — thinking from each user's point of view

Add the following, prioritized by how much they matter to each type of user:

### From the customer's point of view
- **Order status tracking page** — expand the "Orders" tab from v4 into a real order-tracking view: order placed → accepted → preparing → completed, with timestamps, so a customer can check progress without messaging the shop again.
- **Repeat/reorder button** — on a past order, a one-tap "Order again" that refills the cart with the same items.
- **Favorite/wishlist products** — lightweight, session-based (no login needed) so a customer can mark items to order later.

### From the shop (tenant) admin's point of view
- **Dashboard home/overview page** — instead of landing directly on the product list, give tenants a summary dashboard: today's orders, today's revenue, low-stock alerts, and quick links — this is what most SaaS dashboards lead with, and it's currently missing.
- **Low-stock alerts** — flag products nearing zero stock on the dashboard so shop owners restock in time rather than discovering it from a failed order.
- **Simple discount/coupon codes** — let a tenant create a basic percentage or flat discount code, applied at checkout — a common, high-value small-business feature.
- **Export sales report** — a simple CSV/PDF export of the sales report (v1/v4) for a shop owner's own bookkeeping.

### From the super admin's (platform/sales) point of view
- **Revenue dashboard** — total MRR across all tenants, breakdown by plan, and trial-to-paid conversion rate — the metrics that actually matter for running the business (ties back to the PRD's success metrics).
- **At-a-glance tenant health** — flag tenants who are inactive (no orders/logins in X days) so the super admin can proactively reach out before they churn.
- **Manual invoice/payment log** — since there's no payment gateway yet, let the super admin log a payment received against a tenant (date, amount, plan) so there's a proper record instead of just a plan_status toggle.

Build these in rough priority order: tenant dashboard overview and low-stock alerts first (highest daily-use value), then customer order tracking, then super admin revenue dashboard, then the remaining nice-to-haves (coupons, export, wishlist, reorder) as time allows.

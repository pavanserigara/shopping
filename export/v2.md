adminpassword123# Upgrade prompt (v2) — Local Shop OS

Paste this into Antigravity as a follow-up brief, after the v1 build (`antigravity-build-prompt.md`) is working. These are additions and upgrades on top of that existing system — do not rebuild what already works, extend it.

---

## Upgrade 1: Shop directory / clean public URLs

- Every shop's storefront must live at a clean, directory-style public URL: `platform.com/shop/{subdomain}` (already in v1) — confirm this stays human-readable and shareable (no query strings, no IDs in the URL).
- Add a new public **shop directory page** at `platform.com/shops` that lists every active tenant (shop name, category, a small logo/cover image if set, and a link to their storefront). This is a browsable index of all shops on the platform — useful for discovery and for showing prospective tenants "other shops already using this."
- Directory page should support basic filtering by category and a simple search by shop name.

## Upgrade 2: Admin-managed ads (banner + mid-page)

Add a new **Ads** section to the tenant dashboard, separate from Products.

- **Banner ads**: image upload, optional destination link URL, active/inactive toggle, optional start/end date for scheduling. Support multiple active banner images — if more than one is active, the storefront shows them as an auto-rotating carousel at the top of the page, below the header.
- **Mid-page ads**: same fields as banner ads, but these render as a full-width image block injected into the storefront between rows of the product grid (e.g. after every 2 rows of products) — this is the "mid image" placement, like Amazon/Flipkart category banners inside the listing feed.
- Both ad types need an image upload with a preview before saving, and a way to delete or deactivate an ad without deleting the image file history.
- On the storefront, ad images must be responsive — full width on mobile, contained/centered on larger screens — and must not block or overlap the product grid or navigation.
- Track basic ad performance later (clicks) is a nice-to-have, not required this pass — just get upload, scheduling, and display working first.

## Upgrade 3: Multiple product images (image gallery)

- Upgrade products from a single `photo_url` to support **multiple images per product**.
- New `product_images` table: `id, product_id, image_url, sort_order, is_primary`.
- Tenant dashboard product form: multi-image upload with thumbnail previews, drag-to-reorder, and a "set as primary" action (the primary image is what shows on the product grid card).
- Storefront product detail view: image gallery with a large main image and clickable thumbnail strip below it (standard e-commerce product-page pattern) — swiping between images should work on mobile.

## Upgrade 4: Order list — make it genuinely good

Rebuild the tenant order list into a proper, professional order-management view, not a basic table.

- **Filters**: by status (new / accepted / preparing / completed), by date range.
- **Search**: by customer contact or order ID.
- **Sortable columns**: date, total, status.
- **Status badges**: color-coded per status (e.g. new = amber, accepted = blue, preparing = purple, completed = green) for instant scanning.
- **Order detail view**: clicking an order expands (inline or modal) to show the full item breakdown — product name, quantity, price at time of order, and the total.
- **Pagination**: don't load the entire order history at once; paginate or infinite-scroll.
- Keep the same underlying `orders` / `order_items` tables from v1 — this is a UI/UX upgrade on top of existing data, not a schema rewrite (aside from adding indexes on `status` and `created_at` if needed for filtering performance).

## Upgrade 5: Light theme + a real color palette

- Ship a proper **light theme** as the default across both the tenant dashboard and the storefront (if a dark mode already exists from v1 polish, keep it as a toggle — light must be the default and fully finished).
- Suggested palette — apply consistently as design tokens/CSS variables, not ad hoc colors per page:
  - Primary/brand: a teal or deep green (conveys trust and freshness — fits grocery, food, general retail equally well)
  - Accent/CTA: a warm amber or coral for "Add to cart," "Order via WhatsApp," and other action buttons — must stand out clearly against the primary
  - Neutrals: a warm off-white background, dark charcoal (not pure black) for text, light gray for borders/dividers
  - Status colors: standard semantic set for order badges (amber/blue/purple/green as above)
- Apply the same token set to the admin dashboard, the storefront, and the platform landing page so the whole product feels like one brand, not three different tools stitched together.

## Upgrade 6: UI polish pass — desktop and mobile, both

- Tenant **dashboard** (not just the storefront) must also be fully responsive: sidebar nav collapses into a hamburger/bottom nav on mobile, tables become scrollable or stack into cards on small screens, forms remain usable one-handed on a phone.
- Do a full consistency pass: spacing scale, font sizes, button styles, and card styles should match across landing page, storefront, and dashboard — reuse the same Tailwind design tokens everywhere rather than reinventing styles per page.
- Verify at three breakpoints minimum on every page touched in this upgrade: mobile (~375px), tablet (~768px), desktop (~1280px+).

## What NOT to change in this pass
- Don't touch the WhatsApp ordering flow, multi-tenancy/tenant_id scoping, or the super admin panel logic — those stay as built in v1 unless a bug is found.
- Don't add payment gateway or WhatsApp Business API integration — still out of scope.

## Deliverable
All six upgrades working on top of the existing v1 codebase, with the same PHP/MySQL/Tailwind stack, no new frameworks introduced, and a short note in `README.md` listing what changed and any new tables/columns added.

# Upgrade prompt (v8) — Local Shop OS: platform settings, user management, clean URLs, and SEO

Paste this into Antigravity as a follow-up brief, after v1–v7 are built. This pass adds the platform-configuration and user-management pieces that have been missing, changes the storefront URL structure, adds a viral credit footer to every shop, and adds SEO to the landing page. Keep everything from v1–v7 intact — this pass adds a missing layer, it doesn't redesign existing features.

---

## Fix 1: Editable support contact number

- Add a `platform_settings` table (single-row config table) if one doesn't already exist from earlier passes: `id, support_contact_number, site_name, site_logo_url, primary_color, accent_color, updated_at`.
- Super admin gets a **Settings** section where they can edit the support contact number.
- Display this number consistently wherever the platform currently shows or implies support contact (landing page footer, tenant dashboard help/support area, any "contact us" links) — pull it from this single settings row everywhere, don't hardcode it in multiple places.

## Fix 2: Super admin can reset a tenant's password

- In the tenant list/detail view in the super admin panel, add a "Reset password" action.
- Triggering it should either (a) generate a temporary password and display it once to the super admin to relay to the tenant, or (b) send a password-reset link to the tenant's registered email — pick whichever is simpler to implement reliably in this stack; a displayed temporary password is acceptable for this stage given there's no email service integrated yet.
- Log this action (who reset, when) for basic accountability — a simple `admin_action_log` table is enough: `id, actor_admin_id, action, target_tenant_id, created_at`.

## Fix 3: Super admin can manage other super admin users

Currently there's likely only one super admin account. Add proper management of platform-level admin users.

- Extend the existing `admin_users` table's `role` column usage: support at least `super_admin` and `support_admin` (a limited role, if useful — otherwise a single `super_admin` role is fine to start).
- Add a **Team/Admins** section in the super admin panel: list existing super admin accounts, invite/create a new one (email + temporary password, same pattern as Fix 2), and deactivate an admin account if needed.
- Make sure this is itself gated — only an existing super admin can create another one, and a super admin should not be able to accidentally deactivate their own only account (guard against locking everyone out).

## Fix 4: Clean storefront URLs — `mydomain.com/sitename` instead of `mydomain.com/shop/sitename`

Change the public storefront route from `/shop/{subdomain}` to just `/{subdomain}` directly off the root domain, as requested.

- This requires **reserving a fixed list of top-level path names** so a shop's subdomain can never collide with a real platform route — reserve at minimum: `shops`, `login`, `signup`, `admin`, `dashboard`, `settings`, `about`, `contact`, `pricing`, `terms`, `privacy`, `api`, `uploads`, `static`. Enforce this reserved list at signup time (reject a shop name that matches a reserved word) as well as at the routing level.
- Update every existing link across the platform that points to `/shop/{subdomain}` (directory page cards, tenant dashboard "view my storefront" link, order confirmation redirect from v4, etc.) to the new `/{subdomain}` format.
- Confirm this doesn't break the routing for existing platform pages (landing page at `/`, directory at `/shops`, etc.) — test the full route table together, not just the new pattern in isolation.

## Fix 5: Continue landing page improvements

Building further on the v7 SaaS-landing-page rebuild:

- Push for more distinctiveness in the visual design — avoid it looking like a generic template; use the yellow/white brand consistently but with more confident layout choices (asymmetric sections, varied section backgrounds, etc.) rather than a repetitive stack of centered text blocks.
- Continue and refine the scroll-triggered animations from v7 — make sure they feel smooth and don't cause layout jank, especially on mobile.
- Re-verify full mobile responsiveness specifically on this page again — this has been flagged as a repeated problem area, so treat it as a priority checklist item, not an assumption.

## Fix 6: "Powered by" credit footer on every shop storefront

Add a small, consistent footer element at the bottom of every tenant's storefront (not the dashboard — the public customer-facing storefront):

- Text along the lines of: "Powered by [Platform Name] — Create your own online store for free" with the platform name/logo linking back to the platform's landing page.
- Keep it visually subtle (small text, doesn't compete with the shop's own branding) but always present and always a working link — this is the platform's own organic growth loop, every shop becomes a small ad for the platform.
- Should be part of the shared storefront layout/template so it's automatically present on every shop without needing to be added per-tenant.

## Fix 7: Super admin settings — site name, logo, and global theme colors

Extend the Settings section from Fix 1 to also control platform branding:

- **Site name**: editable text, used in the landing page header, browser tab title, and the storefront credit footer from Fix 6.
- **Site logo**: editable upload, replacing the static logo built in v4 — used everywhere the platform logo currently appears (landing page, storefront credit footer, favicon).
- **Global theme colors**: expose the primary (yellow) and accent (CTA) colors from the `platform_settings` table as editable color pickers, so the super admin can adjust the brand palette without a code change. These values should feed the same CSS variables/design tokens used everywhere (from the v3 theme work) — changing them here should update the whole platform's look consistently.
- Changing these settings should apply immediately (or on next page load) without requiring a redeploy.

## Fix 8: Complete user management (this was flagged as still missing)

Build a proper, complete **User Management** section in the super admin panel — this is distinct from the existing tenant list (which is shop/business management) and the admin-team section (Fix 3, which is platform staff).

- List all tenant admin users (the actual login accounts tied to each shop, from `admin_users` where `tenant_id` is not null) — searchable by shop name or email.
- For each: view basic account info, activate/deactivate the account (separate from suspending the whole tenant/shop — an owner might have two staff logins, for example, in the future), and trigger the password reset from Fix 2.
- This section should feel like the single place a super admin goes to answer "who can log into this platform, and as what," covering both tenant-side users and platform admin-side users (linking to Fix 3's team section for the latter).

## Fix 9: SEO for the landing page

- Add proper `<title>` and `<meta name="description">` tags, unique and descriptive, reflecting what the platform does.
- Add Open Graph tags (`og:title`, `og:description`, `og:image`, `og:url`) so the page renders well when shared on social media/WhatsApp.
- Add a `sitemap.xml` (landing page + directory + key static pages) and a `robots.txt` allowing indexing of public pages while disallowing admin/dashboard routes.
- Use semantic HTML on the landing page (proper heading hierarchy — one `h1`, structured `h2`s per section) so it's both accessible and SEO-friendly.
- Add basic structured data (JSON-LD, `SoftwareApplication` or `Organization` schema) on the landing page if feasible — a nice-to-have, not required if it adds too much complexity this pass.

## What NOT to change in this pass
- Don't touch the plan/feature-gating logic from v6, the WhatsApp ordering flow, or the multi-tenancy data model beyond what's explicitly needed for the URL routing change in Fix 4.

## Deliverable
An editable support contact number, tenant and admin password resets, a super admin team-management section, clean `/{subdomain}` storefront URLs with reserved-word protection, a further-polished and verified-responsive landing page, a "Powered by" credit footer on every storefront, a super admin branding settings page (site name/logo/colors) that propagates platform-wide, a complete user-management section covering both tenant and platform admin accounts, SEO tags/sitemap/robots.txt on the landing page, and a short `README.md` note describing what changed and any new tables (`platform_settings`, `admin_action_log`, or similar).
